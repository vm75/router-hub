Route policies

Override settings for part of an app

Each object selects a path and overrides only the settings you provide. Other values inherit the site's effective settings. For a subfolder mounted at /music/, a policy for /api applies to /music/api.

Assign a request budget

Define named limit policies in Global settings, then set "limit_policy":"assets" on a route. Omission inherits from the parent, including nested children; "default" restores the original Ban Shield budget. A policy replaces both base limits. Different names use independent per-IP accounting; the same name shares a budget across sites. The existing rate_limit still adds a supplemental request limit only where specified.

Choose how a path matches

match defaults to "prefix" and covers paths starting with the supplied path. Use "exact" for one URL, "regex" for a case-sensitive pattern, or "regex_i" for a case-insensitive pattern. Query strings are not part of the path match.

Keep administration on the LAN

Allow only clients in your global IP/CIDR allowlist. An empty allowlist denies everyone.

[{
  "path": "/admin/",
  "enable_lanonly": true,
  "spa_fallback": ""
}]

Keep API errors out of the SPA shell

Return the backend's API responses instead of serving the SPA fallback. Disable caching for these responses.

[{
  "path": "/api/",
  "cache_policy": "no_cache",
  "spa_fallback": ""
}]

Stream server-sent events

Use SSE transport for an event endpoint. This streams responses without buffering and uses extended connection timeouts.

[{
  "path": "/events",
  "match": "exact",
  "proxy_transport": "sse",
  "cache_policy": "no_cache"
}]

Combine these objects in one array to use several policies. Explicit false and 0 override inherited values. Nested children inherit their parent policy; their paths are still relative to the app mount.

Setting help

Nginx setup quick reference

Starting points for managed sites. Use the field names below in the site editor; set explicit values when your global defaults differ.

Connect the app

  1. Choose a domain, subdomain, or subfolder and set Upstream URL to the app's internal HTTP/HTTPS address.
  2. Choose LAN only. A public site needs No; a private site needs an allowlist in Global settings. A child cannot remove its parent domain's LAN restriction.
  3. For a domain that serves an app, set Return 404 at domain root to No. Enable subfolders only when needed. Enable a child's parent domain before enabling the child, and configure its TLS certificate.

Uploads, playback, and authentication

  • Body size limit caps request uploads, not downloads. 128M is a starting upload cap; match it to the app's needs.
  • For big media/library uploads, set Large uploads = Yes and choose Large upload limit, for example 1G. This separate limit replaces Body size limit while enabled. Match backend/PHP upload limits too.
  • Stream responses delivers data without response buffering. Byte ranges supports seeking/resuming. Long-lived connections and large uploads use Session timeout (default 3600s); large uploads also use Upload idle timeout (default 3600s).
  • WebSockets work with the default Transport = websocket. Use sse only on an event-stream route. For backends needing HTTP authentication passthrough, such as Calibre, set Backend authentication = Yes.
PWA / SPA: keep API errors real and admin pages private

Only if the app uses client-side routes, set SPA fallback URI to /index.html. Exclude its API/auth paths from that fallback. In Route policies (JSON, optional), adapt these paths and merge with any existing routes:

[
  {"path":"/api/","spa_fallback":"","cache_policy":"no_cache","enable_byte_ranges":false},
  {"path":"/admin","enable_lanonly":true,"spa_fallback":"","cache_policy":"no_cache","enable_byte_ranges":false}
]

Do not use SPA fallback for WordPress. A mounted app must support its public subfolder/base URL. Route paths are relative to the app: use /admin, not /myapp/admin.

WordPress: uncached admin/login and login rate limiting

Set Cache policy = inherit. Add these entries to Route policies (JSON, optional); the bundled login zone is ready to use:

[
  {"path":"/wp-admin/","cache_policy":"no_cache","enable_byte_ranges":false},
  {"path":"/wp-login.php","match":"exact","cache_policy":"no_cache","enable_byte_ranges":false,"rate_limit":{"zone":"wplogin","burst":3}}
]

Normal pages follow the backend's cache headers. Login/admin routes get no-store headers. Configure actual user authentication in WordPress.

Live updates: add an SSE route

If the app exposes an SSE endpoint, adapt its path and merge this entry into Route policies (JSON, optional):

[
  {"path":"/api/updates","proxy_transport":"sse","cache_policy":"no_cache","enable_byte_ranges":false,"spa_fallback":"","proxy_session_timeout":"300s"}
]

This clears Connection and disables response buffering on that route. Other routes retain WebSocket support. Keep Clear Origin header = No unless the backend specifically requires otherwise.

DHCP reservations

Only dhcp-host lines are managed. Interfaces, comments, and other directives are kept in /jffs/configs/dnsmasq.conf.add but are not shown here.
